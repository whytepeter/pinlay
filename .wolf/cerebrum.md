## Key Learnings

- **Data lists use `QueryList`; single-record fetches use `DetailsList`** (`apps/web/src/shared/components/`). Both wrap TanStack Query (`@tanstack/vue-query`; client in `shared/lib/query-client.ts`, registered via `VueQueryPlugin` in main.ts) and own ALL non-happy states — loading skeletons, hard-error + Try-again, empty, background-refetch bar, and (QueryList) pagination/infinite/load-more + a retrying indicator. **Do NOT hand-roll `isLoading`/`isError`/retry in feature components** — pass `queryKey` + `queryFn` and render rows via `#default`/`#item` (QueryList) or `#default="{ data }"` (DetailsList). QueryList `mode`: "load-more" (default) | "infinite" (IntersectionObserver auto-fetch) | "paged" (prev/next, keepPreviousData). Defaults assume the API page shape `{items,total,limit,offset}`; override with `selectItems`/`selectTotal`. The QueryClient does NOT retry 4xx (permanent), retries network/5xx 2× with backoff.
- **Tailwind v4 + monorepo:** the app's CSS must include `@source "../../../../packages/design/src";` (in `apps/web/src/assets/main.css`). Tailwind v4 auto-detection skips node_modules, so classes used inside the `@pinlay/design` workspace package aren't generated without this — components render unstyled.
- **shadcn-vue install:** use the CLI from `packages/design` — `pnpm dlx shadcn-vue@latest add <comp> -y -o`. Requires `components.json` (no `tsx` key) + tsconfig `paths: { "@pinlay/design/*": ["./src/*"] }`. The latest registry imports icons from `@lucide/vue`; repoint those to `lucide-vue-next` after adding. Components import `cn` from `@pinlay/design/lib/utils` (exported in package.json `exports`).
- **Icons:** `@pinlay/design/src/components/Icon.vue` wraps `lucide-vue-next` (kebab `name` → PascalCase). Use `<Icon name="map-pin" />`.
- **Pin marker colour rule** (`AnnotationPin.vue`): colour is ALWAYS `--sev-{low|medium|high|critical}`, regardless of pin state or status. Severity is the at-a-glance signal ("how bad is this?") and is stable for the life of the pin. Status is surfaced via the resolved-checkmark overlay (small green badge top-right) + the detail popover's status dropdown. Resolved pins also get `opacity-55` so they recede. Do NOT switch back to status-driven colour without checking with the user.
- **API stack** (apps/api): NestJS 11 + Prisma 6 + Postgres on Neon. **JWT auth via `@nestjs/jwt` + `bcrypt`** (rounds=12). Single `JwtAuthGuard` handles all routes; mark public endpoints with `@Public()` (decorator at `src/auth/jwt-auth.guard.ts`). The guard verifies a Bearer JWT and resolves the `req.user` shape `{ id, email, name, avatarUrl, workspaceId, role }`. **NO dev/anonymous fallback (removed 2026-05-30):** every protected route requires a real `Authorization: Bearer <jwt>` from `/auth/login` or `/auth/signup`. A tokenless request always `401`s. **`pnpm db:seed`** creates the dev user `you@pinlay.dev` (password `pinlay-dev`) — to call the API in dev you must log in as that user to get a token; there is no longer a header-less shortcut.
- **[2026-05-30] Dev-auth fallback was REMOVED — do not restore it without an explicit ask.** Prior versions of `JwtAuthGuard` resolved tokenless requests to `DEV_USER_EMAIL`. That whole path is gone: guard requires a bearer token, `env.ts` dropped `devAuthEnabled`/`devUserEmail`, `.env` dropped `ALLOW_DEV_AUTH`/`DEV_USER_EMAIL`. **Consequence/open gap:** nothing has a token path yet — the extension popup's `api.me()` will `401` (so it shows "Local" permanently) and the dashboard (pure mock) can't call `/api/sessions` until it can obtain a token. Stale references to the old fallback may still linger in comments (`prisma/seed.ts`, `popup/App.vue`) — treat those as doc-rot, not as a feature to revive.
- **NestJS dev script gotcha:** `nest start --watch` ships with `deleteOutDir: true` by default in `nest-cli.json` AND tsc-watch defaults to `incremental: true` from tsconfig. Together they create a startup race: nest deletes dist/, tsc-watch's incremental cache thinks "nothing changed" and emits nothing, then the launcher tries to fork `dist/main` and crashes with `MODULE_NOT_FOUND`. **Fix:** `deleteOutDir: false` in nest-cli.json + `incremental: false` in tsconfig.json. Pair with `tsConfigPath: tsconfig.build.json` so the build excludes `*.spec.ts` and `prisma/seed.ts`.
- **bcrypt + pnpm:** add `bcrypt` to root `package.json#pnpm.onlyBuiltDependencies` alongside `@prisma/client`, `@prisma/engines`, `prisma`, `@nestjs/core`. Without it pnpm skips the postinstall and the native bindings are missing.
- **`@nestjs/jwt` expiresIn typing:** `signOptions.expiresIn` accepts `ms.StringValue` (e.g. `"30d"`, `"1h"`) or a number of seconds. `ConfigService.get<string>(...)` returns plain string which fails the union narrow. Cast to the template-literal `${number}${"s" | "m" | "h" | "d"}` when reading from env (see `apps/api/src/auth/auth.module.ts`).
- **API env access is centralised in `apps/api/src/config/env.ts`** — `env()` is a validated singleton and the ONLY place allowed to read `process.env`. It throws at boot on prod misconfig (weak JWT secret in prod, missing CORS in prod). Current `AppEnv` fields: `nodeEnv, port, corsOrigins, jwtSecret, jwtExpiresIn, bodyLimit` (the `devAuth*` fields were removed with the fallback). Don't read `process.env` directly anywhere else; add a field to `AppEnv` instead.
- **API rate limiting:** `@nestjs/throttler` — global `ThrottlerGuard` via `APP_GUARD` (100/min/IP) in app.module.ts; tight `@Throttle({default:{ttl:60_000,limit:5}})` on `login`+`signup`. When testing auth endpoints with curl loops, the 5/min limit will bite — wait 60s between bursts or you'll get 429s + empty tokens.
- **Multi-tenant authz pattern:** every cross-entity FK accepted from a DTO (assigneeId, issueId, …) MUST be validated against the caller's `workspaceId` before write — tenant-scoping reads is not enough. See `assertAssigneeInWorkspace`/`assertIssueInWorkspace` in `annotation.service.ts`. Reads/updates/deletes are already scoped via `where: { session: { workspaceId: user.workspaceId } }`.
- **Two API surfaces, two vocabularies — keep them separate.** The extension WRITES via `/api/annotation/*` (pins, sessions/:id/submit) + `/api/attachments`. The dashboard READS via `/api/sessions` (list), `/api/sessions/:id` (detail, pins embedded), `/api/sessions/:id/pins`. Code lives in `src/dashboard/`. The dashboard's "Session" === the API's **Issue** (the titled group created on submit); a `Pin.sessionId` in the dashboard DTO is actually the issue id.
- **API response shape = "best contract", NOT the dashboard's mock shape.** Rules applied in `src/dashboard/dashboard.serializers.ts`: (1) no presentation in payloads — `faviconLabel/faviconHue/urlPath` are client-derived from `pageUrl`, never returned; (2) one vocabulary — `workspaceId` everywhere, never the mock's `orgId`; (3) identifiers not formatted strings — return `number` (raw `Issue.seq`) + `reference` ("PL-0142", API owns the format, like Linear's number/identifier); (4) embed relations the consumer always needs — `reporter`/`author`/`assignee` are compact `MemberRef {id,name,email,avatarUrl}` so the client never joins against a members list; (5) detail embeds `pins` (+ each pin's `attachments`) to avoid a fetch waterfall; (6) keep the canonical field — a pin's `comment` (full markdown) is returned as-is, with `title` as a *derived* first-line convenience, never a replacement. The dashboard's mock (`apps/web/src/shared/lib/data.ts`) must adapt to THIS shape when wired (derive favicon/urlPath client-side, format `reference`, use embedded `reporter` instead of the PEOPLE lookup) — not the reverse.
- **`Issue.seq`** is a global `@unique @default(autoincrement())` (SERIAL) added in migration `20260530030000_issue_seq_dashboard`. Rendered as `PL-{seq padStart 4}`. Global (not per-workspace) is intentional — simplest stable id; workspace scoping on every read prevents cross-tenant id leakage.
- **Prisma `migrate dev` is interactive and FAILS in this non-interactive shell** (esp. with a unique-constraint warning). For schema changes: hand-write the migration dir + `migration.sql`, then `pnpm prisma migrate deploy` (non-interactive) + `pnpm prisma generate`. Don't reach for `db push` — it skips migration history.
- **macOS `echo "$VAR" | jq` corrupts JSON** containing literal `\n`: bash/sh `echo` interprets the backslash-n as a real newline → jq "control characters U+0000–U+001F must be escaped". When testing API responses in Bash, save to a file (`curl -o`) and `jq file`, or use `printf '%s'` — never `echo`.
- **API security posture (verified 2026-05-30 by live attack):** tenant isolation solid (cross-ws read→[], update/delete→404); JWT `alg=none`+tampered→401; no user enumeration (login bad-pw == missing-user message); body-size limited (`express.json({limit: BODY_LIMIT})`, default 10mb); bcrypt rounds=12; helmet on (CSP off — pure JSON API). Still TODO before public launch: audit logging on auth events; consider per-account (not just per-IP) login throttle; move attachments off inline base64 to object storage.
- **Web deploy (Vercel) — `apps/web/vercel.json` (2026-05-30):** web deploys independently from the monorepo (api ships to its own host). `@pinlay/design` + `@pinlay/shared` are **source-only just-in-time packages** (`exports` → `./src/*`, no `dist`/build step); Vite compiles design's `.vue` SFCs into the web bundle at build time, referenced from `../../packages/design/src` via the `@ui` alias AND the Tailwind `@source` in `main.css`. vercel.json: `installCommand: pnpm install --filter @pinlay/web...` (skips api's prisma/bcrypt/nestjs native deps, still links workspace symlinks), `buildCommand: vite build` (deliberately NOT `pnpm build` — the build script's `vue-tsc --noEmit` follows imports into design/src so a type error there would fail the web deploy; run vue-tsc in CI instead), `outputDirectory: dist`, `rewrites: /(.*)→/index.html` (SPA fallback — router uses `createWebHistory()`). **Dashboard-only settings vercel.json can't set:** Root Directory=`apps/web`, "Include files outside Root Directory"=ON (⚠️ required — build reads `../../packages`; off = `Cannot find module '@pinlay/design'`), env `ENABLE_EXPERIMENTAL_COREPACK=1` (honor pnpm@10.12.1 pin). Prod API URL: the `/api`→:8787 vite proxy is DEV-ONLY; prod web must call api by absolute URL via env (e.g. `VITE_API_URL`) once mocks (`shared/lib/data.ts`) are swapped for real fetches. Future repo-split: only `@pinlay/shared` crosses the web↔api boundary (design is shared with the extension, not api) — publish shared (+ design with a compiled dist) and flip `workspace:*`→versioned. - [2026-06-03] Don't rely on monkey-patching `history.pushState`/`replaceState` to detect SPA navigation in a content script — host SPA routers (Nuxt/Vue Router/React Router) capture the original `pushState` at page load, BEFORE our patch installs, so their navigations call the saved original and bypass us; `popstate`/`hashchange` don't fire on pushState either. Add a cheap normalized-URL `setInterval(onLocationMaybeChanged, 500)` poll as the catch-all (clear it on unmount). Without it, `AnnotationOverlay.livePageUrl` froze at the mount-time URL → pins from the old route showed as "element not found" on the new route AND new pins persisted under the stale `pageUrl`. See `bug-277`.
- [2026-06-03] Don't mutate a textarea's bound value directly (`description.value = …`) from buttons that edit the text — Bold/Italic/Link etc. A direct v-model mutation **bypasses the textarea's native edit pipeline**, so the change isn't added to the browser undo stack and Cmd+Z silently skips over the toolbar action. Route the replacement through `document.execCommand("insertText", false, replacement)` after `el.focus() + el.setSelectionRange(start, end)` — it goes through the edit pipeline and IS undoable. Keep a direct-mutation fallback. Also: toolbar buttons that operate on selection need `@mousedown.prevent` so the click doesn't steal focus from the textarea (which would defeat execCommand and break selection-based wrapping). See `bug-283`.
- [2026-06-03] Don't ship a `<button>` with only `display/size/color` overrides — native buttons carry default background, border, and padding chrome. In `<style scoped>` (Vue) or any utility-only approach, ALWAYS include the resets: `border-0 bg-transparent p-0 cursor-pointer` (Tailwind) or equivalent. Otherwise browsers paint their default gray-bevel button under your icons. Also: this project's rule is no hand-written component CSS at all (cerebrum) — use Tailwind utilities. See `bug-282`.
- [2026-06-03] Don't `await` attachment uploads serially before closing a composer/dialog — the user perceives the dialog as "hung" for `1 createPin RTT + N upload RTTs`. Close the dialog + push the persisted entity as soon as `createPin` returns (the id is already known); fire attachment uploads in **parallel via `Promise.all`** as background work; surface failures via a warning toast/log rather than blocking the dialog. - [2026-07-08] Helmet's defaults set `Cross-Origin-Resource-Policy: same-origin` on EVERY response, including anything served by an `express.static` mount registered on the Nest app. If the API and web dev servers are on different origins (`:8787` vs `:5173`), `<img src="…api-origin…">` is blocked with `net::ERR_BLOCKED_BY_RESPONSE.NotSameOrigin` — even though CORS on the fetch itself is fine (image loads don't use CORS). - [2026-07-08] class-validator's `@IsUrl()` defaults reject any hostname without a public TLD (`localhost`, `127.0.0.1`, LAN IPs). ## Anchor resilience (apps/extension/src/lib/anchor.ts) — 2026-05-30
- **Graded resolveAnchor**: stable-attr → selector → xpath → attribute-fingerprint → text+ancestor-fingerprint → role+accessibleName → null. Returns `{el, confidence: AnchorConfidence}`. Consumers (AnnotationOverlay.vue) only read `.el` + null-check, so the confidence union is safe to widen.
- **Fingerprint CONFIRMATION is the key idea**: a structural locator (`button:nth-of-type(2)`) silently matches the WRONG node after a sibling reorder. So selector/xpath hits are confirmed via `confirmsStored(el)` (attributeFingerprint OR textFingerprint must match); an unconfirmed hit is held as a `weak` fallback while the heuristic fingerprint tiers try to re-find the real element, and only returned if they all miss. stable-attr is trusted without confirmation (a test id IS the identity). Without this, reorder returns a wrong-but-existing element.
- **describeAnchor** now also captures `xpath, accessibleName, textFingerprint, attributeFingerprint, ancestorFingerprint` (all OPTIONAL → legacy pins still resolve). Named to match the shared `Anchor` zod schema (which already had these fields unused) to ease the eventual PinAnchor↔Anchor reconciliation (owned by the API session). Anchor is sent to the API as an opaque `Record<string,unknown>` blob, so adding fields is wire-safe.
- **anchorHealth(confidence)** → "ok" (stable-attr/selector/xpath) | "fallback" (attribute/text/role) | "dead" (null). Seeds the Roadmap 1.1 dashboard health badge.
- **Test harness (Roadmap 1.2)**: `apps/extension/test/anchor.test.ts` + `vitest.config.ts` (jsdom env), script `pnpm --filter @pinlay/extension test`. Pins a fixture element, mutates the DOM (rename classes, reorder, wrap-in-div, edit copy, remount-clone, insert section, ambiguous-dupe), resolves, asserts it re-found the exact node via a `data-truth` oracle attr (invisible to the resolver — not in STABLE_ATTRS/FINGERPRINT_ATTRS). **7/7 jsdom-judgeable = 100%**. jsdom CAVEAT: no layout (getBoundingClientRect→0, so rect tie-break blind) + no document.evaluate (xpath tier no-ops, caught by try/catch) → results are a conservative lower bound; ambiguous-dupe scenario is marked browser-only.
- **Tooling fixes done this session**: added `vite` devDep (env.ts uses import.meta.env → needs vite/client types; was bug-151) and added `.wxt/wxt.d.ts` to `apps/extension/tsconfig.json` include (the custom include was overriding WXT's and dropping auto-import types → createShadowRootUi/autoIcons errors).
